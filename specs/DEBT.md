| DEBT-009 | `clientIp()` trusts `x-forwarded-for` — **confirmed spoofable, and now narrowed** (SEC-032, Phase 9 §9.1). It takes the _leftmost_ entry, which is the one a client sets; behind a proxy that appends rather than replaces, every request can claim any address. What rides on it: OTP send/verify, login, claim-token, share, enquiry and bill-create limits, plus §9.1's global limit. Per-identifier limits are unaffected, which keeps this MEDIUM. Two halves: (a) code — take the rightmost entry with an explicit trusted-hop count, and fall back to the rightmost _public_ entry when the selected one is private/loopback/link-local, so a wrong hop count cannot put every visitor in one bucket and lock out the site; (b) ops — send a forged header through the real deployment and log what arrives. Keep open until (b) has been run against production. **Phase 9 §9.1 — half (a) is DONE.** `clientIpFromHeaders` reads from the right with an explicit `TRUSTED_PROXY_HOPS`, and never accepts a private, loopback, link-local or CGNAT address as an identity — so a wrong hop count degrades to the rightmost public entry instead of collapsing every visitor into one bucket. Half (b), the ops confirmation, is still owed and is why this stays open.
